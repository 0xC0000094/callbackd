# Playbook: Investigation

**You own a cited answer. You change no code.**

Use it for a question about the code: how something works, why it was built this way, or whether a claim is true.

## Steps

1. Restate the question in one sentence.
2. Trace the code that answers it. Use read-only delegates for large areas.
3. For "why" questions, read the history: the commits and pull request discussions that added the code and changed it.
4. Separate the evidence from your guesses. Say what data you used.
5. If the premise of the question is wrong, say so.
6. Write the answer in this form: Overview, Key concepts, How it works, Where things live, Gotchas. For a choice between options, add a table of tradeoffs.
7. Say what the record does not answer. "Nobody wrote down why" is also an answer.

## Exit

- No code change and no pull request.
- If the answer points to a fix, start the fix as a new task.
